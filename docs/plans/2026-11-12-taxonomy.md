**Goal:** Releases carry the Pháp điển subject tree with seed assignments, agents and the website read it and filter search by it, and the website gains topic pages and the node, type and issuer filters.

**Architecture:** A pure-Go reader parses the pinned 2023 package; `corpus taxonomy import` keeps `taxonomy/mapping.yaml` (GUID to stable code); the build stage loads nodes, seeds and manual overrides into the release (corpus schema 5) with the family precedence and subtree counts; the retrieval engine serves the tree, reorders search by one filter predicate and pages it with a digest-bound cursor; MCP, the web API and the website consume those engine calls.

**Tech Stack:** Go 1.27.3 (stdlib `archive/zip`, `encoding/json`, `golang.org/x/text/unicode/norm` already in the module), PostgreSQL 18 with ltree, pgx v5, the existing MCP SDK, OpenAPI 3.1 and openapi-typescript, Nuxt 4 as in Plan 10.

## Global Constraints

- Package `BoPhapDienDienTu.zip`, SHA-256 `dc2fc7d14e208b551e3e7667e911dcfd24d8f246a7e24d3d24ad7507cd4b5ff5`, never committed; tests use a synthetic package with freshly written text; package article text and notes are never stored or served (ADR 0004).
- Codes follow the import table in taxonomy.md exactly; a code is never reused; a GUID keeps its code across imports.
- `taxonomy_version` = SHA-256 over the length-prefixed bytes of `mapping.yaml`, `custom.yaml`, `overrides.yaml` in that order; it enters the build input hash.
- Family precedence (data.md): within a family a provision holds one method; `manual` replaces `phapdien_seed` and `llm`, a seed replaces `llm`; a manual `exclude` removes the family and blocks automatic entries; all in one transaction.
- Effective nodes are resolved per family along the provision's ancestry (nearest provision with an entry in that family decides; precedence and `exclude` applied there); they drive hits, filters and counts. Served node: `active` with at least one effective assignment in its subtree; anything else is unknown to every read path and filter (`invalid_request`).
- Filters are ordering preferences and never hide. Paging walks one list in two groups: primary hits shaped at the list cap 100 and non-current hits shaped at 100; each page holds at most `limit` hits split by group. Unfiltered: the first page is exactly today's response. Every other page fills from what remains of each group (with `in_force_only` true up to the effective non-current tail from the non-current group, the rest from primary; with false primary first; then non-current takes slots primary cannot fill); later unfiltered pages skip the hits the first page showed. Filtered: each group ordered inside first, pages fill from the start of the reordered groups by the same rule, `in_filter` on every hit, `outside_filter_count` over the whole list.
- The cursor holds release, the first page's `limit`, the hits taken so far from each group, the resolved `as_of` date and a SHA-256 digest of the request without `cursor` and `limit`; never query text; activation (Plan 11) checks that a release's schema version is among those the server reads (deployment.md).
- Limits (budgets): `nodes[]` 20, `doc_types[]` 10, `issuers[]` 10, `documents[]` 20; `taxonomy` depth 3 (default 1), `q` 100 code points, 500 nodes per response, 20 documents per node page.
- Corpus schema 5: the release row is version 5; the server reads versions 4 and 5 and a version-4 release serves no nodes, so no lockstep switch is needed and rollback is reactivating the previous release; the coordinator schedules a version-5 baseline run once Task 4 merges.
- Typed node lookup text never leaves the browser: the web taxonomy route has no `q`; the picker matches locally over loaded nodes; MCP keeps `q` (JSON-RPC body).
- Web: node codes match `^[1-9][0-9]{0,2}(\.[1-9][0-9]{0,3}(\.[pcx][1-9][0-9]{0,3}(\.[cmx][1-9][0-9]{0,3})?)?)?$`; filters and the query stay in component state, except `node` arriving from a topic link (allowlisted in `next`); no `v-html`; files at most 400 lines.

## Review Focus

- A code that changes or is reused between two imports of a moved or removed node: users' links and filters would silently point elsewhere. Task 2 `TestImport_StableAcrossReorder`, `TestImport_RetiredCodeNeverReused`.
- A seed attached to the wrong provision (an article number with a letter suffix, a numeric ItemID that is also part of a UUID key, an article listed twice): wrong subject on law. Task 4 `TestSeeds_ExactItemIDAndArticle`.
- A filter that hides a hit or changes the unfiltered order: Task 6 `TestFilter_PermutationOfUnfiltered`, `TestSearch_NoFilterUnchanged`.
- A cursor replayed with another query, filter or release, or one that carries text: Task 6 `TestCursor_BoundToRequestAndRelease`.
- A retired or empty node listed on a topic page or accepted by a filter: Task 5 `TestTaxonomy_OnlyServedNodes`, Task 6 `TestFilter_UnservedCodeInvalid`.
