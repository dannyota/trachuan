**Goal:** The website: public pages without an account, Google sign-in through the server's login routes, search and the document reader for signed-in users, and the account page, in Vietnamese with optional English.

## Global Constraints

- Questions are never stored (ADR 0002): search sends the query only in a `POST` body from the browser; the query never appears in a URL, route, page title, history entry, `localStorage`, `sessionStorage`, a cookie, analytics or a log line, and signed-in search results are never server-rendered or cached.
- Same origin as the Go server (web.md "Routing"); local development on `http://localhost:3000` with the dev proxy for `/api/*` to `http://127.0.0.1:8080` and `SERVER_PUBLIC_URL=http://localhost:3000`.
- Nitro route rules cache only public routes (`/`, `/connect`, `/sources`, `/privacy`, `/terms`, `/llms.txt`) for 600 s, keyed by path and the normalized language (`vi` or `en`; any other cookie value is `vi`), never by raw cookies; signed-in routes send `Cache-Control: no-store` and are never cached.
- Public HTML is rendered anonymously: no session lookup and no account data in a cached response; the header's sign-in or account link is decided after hydration by one optional browser probe of `GET /api/v1/me`, whose 401 means signed out: the public page stays and shows the sign-in link, with no redirect.
- Public admission in Nitro per budgets: 120 requests per minute per client address (same trusted-proxy rule as the server), at most 4 concurrent uncached renders, excess answered at once with 429 and no queueing.
- On uncached signed-in SSR, `Set-Cookie` headers from same-origin API calls (session renewal) are forwarded to the browser response; public SSR makes no session call.
- Unsafe API calls send `X-CSRF-Token` from `GET /api/v1/me`; on signed-in routes and user actions, a 401 leads to `/api/v1/auth/google/start?next=<current path>` following the web-api.md `next` rules; a 403 `csrf_rejected` refetches `/api/v1/me` once and retries once, only when the account is the one the action started with; otherwise the action is abandoned and nothing is retried. An action captures the account id and CSRF token when it starts (a dialog action when the dialog opens) and sends that token, so a session switched in another tab cannot complete it.
- Language: cookie `lang` (`vi` default, `en`), read on the server for SSR; interface strings in `apps/web/i18n/{vi,en}.ts`; legal text, citations and document numbers are never translated.
- CSP is a static header (the aboutme pattern, `apps/web/app/utils/csp.ts` there): `default-src 'self'`; `script-src 'self'` without `'unsafe-inline'` or `'unsafe-eval'`, the hydration payload externalized into a same-origin script; `style-src 'self'`; fonts and images `'self'`; `connect-src 'self'`; `frame-ancestors 'none'`; `form-action 'self'`; no nonces, so cached and fresh pages carry the same policy; no third-party host anywhere. Fonts self-hosted (Be Vietnam Pro for interface, a serif for law, a monospace for numbers; OFL licences kept beside the files).
- Legal text and any API string render as text, never through `v-html`.
- Personal tokens are shown once on creation, kept only in component state, and cleared on navigation; never stored in Pinia, storage or logs.
- Component and source files at most 400 lines; tests `<subject>.test.ts` (Vitest) and `<feature>[-<scenario>].spec.ts` (Playwright).

## Review Focus

- A query leaking through a URL, history, storage or a server render: Task 4 `search-privacy.spec.ts` and `search-state.test.ts`.
- A signed-in response cached by Nitro or served to another visitor: Task 1 `route-rules.test.ts`, Task 6 `account-no-store.spec.ts`.
- An unsafe call without the CSRF token, or a retry loop on 403: Task 2 `api-csrf.test.ts`.
- API or legal text interpreted as HTML: Task 5 `reader-text.test.ts`.
- A personal token surviving after the creation dialog closes: Task 6 `token-once.spec.ts`.
