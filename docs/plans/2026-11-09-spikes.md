# Spikes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Answer the three questions the design leaves open before code is written: which OAuth server source works with real MCP clients, which dense embedding recipe serves Vietnam on ARM64, and how much of the corpus the 2023 Bộ pháp điển package labels.

**Architecture:** Throwaway scripts under `spikes/` run against a local PostgreSQL restored from banhmi's Vietnam dump. Each spike ends in a research note under `docs/research/` and an ADR History line. Nothing under `spikes/` is imported by `apps/`.

**Tech Stack:** Podman compose, PostgreSQL 18 with pgvector, Python 3.14 with uv (optimum, onnxruntime, sentence-transformers, psycopg), aboutme.vn production for OAuth, one temporary EC2 `t4g.large`.

**Spec:** `docs/design/README.md` (spikes paragraph), `docs/design/taxonomy.md`, `docs/design/auth.md`, `docs/design/budgets.md`, `docs/research/phap-dien-2026-11-08.md`.

## Global Constraints

- Code under `spikes/` is throwaway: labeled in `spikes/README.md`, never imported by `apps/`, deleted by Plan 1 or 2 when the real code lands.
- No banhmi Go package is copied (ADR 0001). banhmi binaries may be run as tools.
- Dumps, models and vectors live under `work/` (gitignored). No user data exists in this plan.
- Queries used for measurement come only from `banhmi/deploy/eval/golden.json`.
- Parity gates from the banhmi embedding spec: FP32 vs INT8 cosine median at least 0.995 and minimum at least 0.98 over 1,000 probes.
- Dense-only recall@8 is the comparison metric; hybrid recall through banhmi's `cmd/eval` is optional.
- Graviton measurement runs on `t4g.large` in ap-southeast-1 for at most 2 hours and the instance is terminated in the same session.
- Documents in English; discussion with the owner in Vietnamese.

## Review Focus

- Latency measured on an M5 Max is not Graviton latency: Task 3 Step 7 repeats the soak on `t4g.large` and the note reports both.
- INT8 query vectors against FP16 stored document vectors can lose recall even when probe cosines pass: Task 3 Step 5 measures recall with stored vectors and with re-embedded vectors.
- A hosted connector that cached a failed first attempt can mask a later success: Task 2 uses a fresh connector name per attempt and records the attempt number.
- Article numbers change across amendments and consolidated texts: Task 4 Step 5 classifies every unmatched article by reason instead of reporting one percentage.
- A PostgreSQL 17 dump restored into 18 with a newer pgvector can silently change HNSW behavior: Task 1 Step 4 records both versions and reruns one stored query against counts from banhmi's PLAN.md.
